## 2. T1：场景草稿隔离（问题 1，P0）

### 现状
- `useStore` 只有**一份**全局草稿：`prompt`（输入框文本）、`params`、`inputImages`。
- `setActiveScene`（`store.ts:925-935`）仅做 `applySceneDefaults`：按场景 defaults 重算 size + 透明开关（`store.ts:2405-2421`），其余不动。
- 结果：在通用创作写了一半的提示词，切到人像写真再切回来，内容互相污染；参数同理。

### 第一性原理
场景 = 独立工作流上下文。草稿是工作流状态的一部分，**上下文切换时状态应随场景走**，而不是全局复用一块黑板。场景 defaults 只应作为"该场景第一次进入时的初始值"，而不是每次切换都覆盖。

### 设计
1. **数据结构**（store）：
   ```ts
   sceneDrafts: Record<SceneId, { prompt: string; params: TaskParams; inputImageIds: string[] }>
   ```
2. **切换算法**（`setActiveScene` 内）：
   - 离开旧场景：`sceneDrafts[old] = { prompt: 当前prompt, params: 当前params, inputImageIds: 当前inputImageIds }`
   - 进入新场景：若 `sceneDrafts[new]` 存在 → 整体载入（prompt/params/图片）；不存在 → 首次进入：params 以场景 defaults 初始化（现有 `applySceneDefaults` 逻辑），prompt 置空，图片置空。
   - **落库**：sceneDrafts 随 persist 持久化（刷新不丢）。
3. **输入图隔离**：v1 一并隔离（inputImageIds 数组引用即可，图片资产本身仍在全局 IndexedDB，不复制数据，只存 id 列表）。注意 `@图N` mention 的序号是按当前 inputImages 列表的——隔离后各自成套，语义自然正确。
4. **skill 场景**：不使用底部 InputBar（有独立输入区），`sceneDrafts['skill']` 不参与；`composeHidden` 逻辑不变。
5. **迁移**：首次升级后第一次 `setActiveScene` 时，把当前全局草稿写入 `sceneDrafts[当前场景]`，避免"升级即清空"。
6. **不做的**：不加"切换确认"弹窗（打断心流）；不做 per-scene 历史记录（已有 promptHistory 全局机制，保持）。

### 验收
- 通用创作输入"ABC"+9:16 → 切人像写真：输入框为空、params=人像 defaults → 切回通用创作："ABC"+9:16 完整恢复（含输入图）。
- 刷新页面后隔离状态保持。
- skill 场景行为不变；engine 模式不受影响。
- 新增 store 测试 ≥4 条（保存/载入/首次初始化/迁移）。

## 3. T2：编辑链路画幅控制（问题 2b，P0）

### 根因回顾（实证）
网关编辑链路输出画幅 = **输入图原尺寸**（两个 API 模式都如此）。所以：输入 5:4 图 + 配置 9:16 → 出 5:4 源图 → 本地 exact-size cover 裁切掉 ~49% 宽度（正是用户看到的 1312×1199 → 2160×3840 警告）。

### 方案：三层防御
**第一层（主力）：输入图预归一 `inputRatioPolicy`** —— 提交编辑任务前，把输入图处理到目标比例，让"锁输入尺寸"的网关乖乖输出目标画幅：
- 策略 a **裁切（cover）**：等比裁输入图到目标比例（几何安全，复用 `computeExactSizeDrawPlan`）。构图损失与现在输出侧裁切等价，但**模型看到并按最终画幅构图**，主体被切概率低得多。
- 策略 b **智能扩边（outpaint，推荐默认）**：把输入图等比缩放置于目标画布中央，两侧/上下用**镜像+羽化边缘**填充成自然延伸，再配提示「补全画面边缘内容，与原图无缝衔接」。网关锁定输入尺寸的特性反而成为优点：输出即目标画幅。
- 策略 off：现状（不做预处理）。
- 入口：参数区新增「输入图比例」下拉（自动=按当前尺寸策略 / 裁切 / 扩边 / 关闭），默认 **裁切**；详情页记录所用策略。
- 实现要点：纯前端 canvas（已有 `exactImageSize.ts`/`imageResizer.ts` 基建）；扩边在提交时才生成预处理图，同时把原图保留在任务记录（`exactSizeOriginalImages` 同款语义）。

**第二层（兜底）：输出比例校正** —— 非 exact_size 任务若返回比例与请求偏差 >5%，本地等比 cover 裁到请求比例（复用现有管线），详情页标注「已校正」。exact_size 已有此行为，本层只是把保护扩展到普通任务。设置项「比例自动校正」默认开。

**第三层（透明化）：请求/返回参数对照** —— 任务详情新增「请求参数 vs 返回参数」分组显示（现在质量已双显 `max｜auto`，补齐 size 双显 + 偏差高亮），并把**最终发出的 tool config / image 参数**存入任务诊断字段，用户不用再猜网关做了什么。

### 顺带修正
- `createResponsesImageTool` 的 `!profile.codexCli` 门控（size/quality）保持不变（真 Codex CLI 兼容需要），但在档案编辑页给 codexCli 开关补一句说明：「开启后 responses 工具的 size/quality 不发送」。

### 验收
- 5:4 输入图 + 9:16 配置 + 策略=裁切 → 网关返回 9:16 源图（尺寸≈输入图面积档），无大幅裁切警告。
- 策略=扩边 → 返回 9:16 且边缘内容为生成延伸（目视无缝）。
- 策略=关闭 → 现状行为 + 输出比例校正兜底生效。
- 详情页可看到请求 vs 返回对照。

## 6. T5：扩写质量重构（问题 3b，P0，核心体验）

### 根因分析（第一性原理）
1. **角色错位**：skill 正文放进 `instructions`，但没有任何"这是必须逐条执行的规范"的框架语，模型把它当参考资料自由发挥。
2. **契约稀释**：输出契约（条数、`### 01` 编号、纯自然语言、禁止字段标签）只在末尾一行带过，几百行规则把它淹没了。
3. **无校验回路**：输出不合格（条数不够/带结构化字段/解析失败）没有检测与重试。
4. **单轮直出**：这些 skill 本质是"变量池×组合规则"（表情/服装/场景/焦段/机位…），单轮直出让模型同时做"抽变量"和"成文"两件事，两者都容易糊。

### 方案
**A. 指令结构重构**（`buildExpansionInstructions` 重写，`skillExpansionApi` 消息结构同步调整）：
```
[instructions]
你是专业的图片生成提示词工程师。下面给出一份 SKILL 规范，你必须逐条遵守它的一切要求
（风格、随机变量表、禁止事项、输出格式）。用户输入是对本次生成的锚点要求，优先级高于
skill 中的默认值，但不得违反 skill 的禁止事项。

<skill>
{skillBody}
</skill>

输出契约（必须满足，缺一不可）：
1. 输出恰好 {N} 条提示词，每条以「### 01」样式编号开头；
2. 每条是一段完整自然语言提示词，禁止出现「场景：」「焦段：」等结构化字段标签；
3. 每条之间场景/瞬间/景别/焦段/机位/构图/前景/光线至少 5 个维度明显不同；
4. 不输出任何解释、分析、变量说明。

[input]
{userInput}
```
关键点：契约**首尾各出现一次**（开头框架+结尾契约）；skill 用明确标签包裹；锚点优先级规则显式化。

**B. 两段式生成**（可选增强，设置开关「严格模式」，默认开）：
- 第一轮：要求模型先输出变量抽取结果（紧凑 JSON：每条的 场景/瞬间/景别/焦段/机位/构图/前景/光线 抽自 skill 变量池，条间去重）；
- 第二轮：把 JSON 作为输入，要求逐条成文（同一会话或两次调用）。
- 好处：可控、可审计（第一轮 JSON 展示给用户看，用户可手动改再成文——进阶交互）。
- 实现为 `runSkillExpansion` 的模式分支，保留单轮模式作为回退。

**C. 解析后校验 + 一次自动重试**（`runSkillExpansion` 内）：
- 校验项：条数 ≥ 期望条数（或 ≥2）；不含字段标签正则 `[\u4e00-\u9fff]{2}[:：]` 高频集合（场景/焦段/机位/构图/光线/服装）；每条长度 ≥ MIN_ENTRY_LENGTH。
- 不合格 → 以 errorMessage 附加重试一次（提示模型具体错在哪）；仍不合格 → 返回已有结果 + UI 黄条警示「扩写可能不符合 skill 规范，可点击重试」。

**D. 单条重 roll**：条目卡新增「重写」按钮——携带该条编号与「替换第 N 条，其余不变」的约束重新生成该条（复用同一扩写链路，N=1）。

**E. 扩写模型透明化**：工坊头部显示当前扩写走的文本档案与模型名；场景设置里可换（已有 textProfileId 路由，补 UI 显示即可）。

**F. 内置 skill 附示例**：两个内置 SKILL.md 各追加一节 `## 示例输出`（1 条高质量示例），指令中声明「参照示例的风格与密度」。（few-shot 对遵循度提升显著。）

### 验收
- vibeshot skill + 锚点「荷塘」→ 10 条全部：自然语言段落、无字段标签、场景/焦段/机位等 ≥5 维度多样、含荷塘锚点。
- 故意触发不合格输出（改小 MIN 条数）→ 自动重试一次 → 警示条出现。
- 单条重 roll 只替换该条。
- 严格模式关闭时回退单轮，行为不劣于现状。

## 8. 实施顺序与依赖

